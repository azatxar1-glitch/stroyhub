# Личные финансы — учёт, баланс, долги, прогноз

Локальная система управления личными финансами: **Python + SQLite + веб-интерфейс**.
Без внешних зависимостей (только стандартная библиотека Python 3.10+), данные хранятся
в одном файле на вашем компьютере и никуда не отправляются.

Отвечает на главные вопросы в любой момент:
**сколько у меня реально денег, сколько я должен, сколько должны мне, какие платежи впереди
и сколько можно тратить до следующего дохода.**

## Быстрый старт

```bash
cd finance
python -m fin serve --open        # веб-интерфейс: http://127.0.0.1:8765
```

На Windows — двойной щелчок по `start.cmd`.

База создаётся автоматически: `finance/data/finance.db` (папка в `.gitignore`).
Другой путь: `python -m fin --db путь/к/файлу.db serve` или переменная `FIN_DB`.

### Первые шаги (порядок важен)

1. **Счета** — каждый счёт с **фактическим** остатком, который вы видите в банке, на сегодняшнюю дату.
   Кредитная карта — счёт типа «Кредитная карта» с отрицательным остатком (это долг).
   Квартира/машина — тип «Имущество» с вашей оценкой (влияет только на чистый капитал).
2. **Долги** — по каждому кредиту и каждому человеку: остаток, ставка, минимальный платёж, день платежа,
   срок, приоритет. Неизвестное оставляйте пустым — система покажет «неизвестно», а не ноль.
3. **Мне должны** — кто, сколько, когда обещал вернуть.
4. **Платежи** — обязательные регулярные платежи (аренда, ЖКУ, связь). Минимальные платежи по долгам
   подтягиваются из раздела «Долги» автоматически.
5. **Ожидаемая зарплата** — операция «Доход» со статусом «Запланирована» на дату выплаты.
   Она **не** входит в доступные деньги, но задаёт горизонт прогноза. Когда деньги пришли — кнопка
   «проведено» в списке операций (можно поправить дату и сумму).
6. Дальше — записывайте операции (`+ Операция`) или импортируйте CSV.

Пароли, коды подтверждения и доступ к банкам системе **не нужны** и не запрашиваются.

## Команды

Режимы `/add … /income` доступны и в веб-интерфейсе (одноимённые разделы), и в командной строке:

| Режим | Командная строка | Что делает |
|---|---|---|
| /add | `python -m fin add расход 1250 -a "Дебет" -c "Продукты и питание" --sub Магазин` | добавить операцию |
| /balance | `python -m fin balance` | баланс: доступно, накопления, долги, дебиторка, чистый капитал |
| /debts | `python -m fin debts --extra 10000` | долги, просрочки, история, порядок и сроки погашения |
| /budget | `python -m fin budget --month 2026-11 --set "Продукты и питание" 25000` | лимиты против факта |
| /salary | `python -m fin salary` | распределение денег до следующего дохода |
| /report | `python -m fin report --start 2026-10-01 --end 2026-10-31`, `--out отчёт.md` — полный | отчёт за период |
| /forecast | `python -m fin forecast` | прогноз остатка до следующего дохода, риск кассового разрыва |
| план | `python -m fin plan 2026-12-31` | план денег по дням через несколько выплат: минимальный остаток, периоды в минусе, итог на дату |
| /goals | `python -m fin goals` | прогресс и сроки целей |
| /audit | `python -m fin audit` | проверки расчётов, утечки, риски, рекомендации |
| /income | `python -m fin income` | доход по месяцам против целей + стратегия роста |

Служебные: `check` (проверки), `backup`, `backups`, `restore ФАЙЛ`, `export`, `import ФАЙЛ`, `init`.
Все отчёты принимают `--date ГГГГ-ММ-ДД` — посмотреть состояние на прошлую дату.

## Правила учёта (защита от двойного учёта)

| Вид операции | Счёт | Долг / дебиторка | В расходах/доходах |
|---|---|---|---|
| Доход | + | — | доход |
| Расход | − | — | расход (только потребление) |
| Перевод между своими счетами | − / + | — | нет; перевод на накопительный/вклад/брокерский = «накопления» |
| Платёж по долгу | − | тело долга уменьшается на «основной долг» | только проценты (= платёж − основной долг) → «Кредиты и проценты» |
| Получен заём | + | долг растёт | нет (заём — не доход) |
| Сверка остатка долга | — | ± | нет |
| Дал в долг | − | дебиторка растёт | нет |
| Мне вернули долг | + | дебиторка уменьшается | нет (не доход и не идёт в цель по доходу) |
| Доход с выбранным дебитором | + | дебиторка уменьшается | доход (задержанная зарплата, оплата заказчика за сделанную работу) |
| Корректировка счёта | ± | — | нет (сверка с банком, переоценка имущества) |

Категории «Возврат личных долгов», «Накопления и инвестиции», «Возвраты долгов» — служебные:
их нельзя выбрать для обычного расхода/дохода, они ставятся автоматически видами операций выше.
Это и есть защита от смешивания расходов, переводов, погашения основного долга и накоплений.

Статусы: «Проведена» — влияет на остатки; «Запланирована» — только в прогнозе (план расходов
уменьшает прогноз, план дохода — никогда); «Отменена» — ни на что не влияет.

## Как считается

Все суммы — целые копейки, без ошибок округления.

- **Фактически доступно** = остатки наличных и дебетовых счетов (+ переплата по кредитке).
  Кредитный лимит, ожидаемые поступления и дебиторка — не деньги.
- **Остаток счёта** = начальный остаток + проведённые операции с даты начального остатка.
- **Долги банкам** = кредиты/ипотека/рассрочки + задолженность по кредиткам; **долги физлицам** — отдельно.
- **Чистый капитал** = доступно + накопления + инвестиции + имущество + дебиторка − все долги;
  консервативный вариант — без дебиторки.
- **Денежный поток за период:** доходы; расходы (потребление, включая проценты); погашение тела долга;
  «доход − потребление»; «свободный поток после долгов»; отложено в накопления; новые займы.
  **Норма сбережений** = (доход − потребление) / доход.
- **Обязательные платежи:** регулярные платежи + минимальные платежи по долгам + сроки возврата
  личных долгов + запланированные расходы. Оплачено = есть проведённая операция, связанная с платежом
  (для долгов — платёж по этому долгу в том же месяце).
- **Прогноз до дохода:** горизонт — дата ближайшего запланированного дохода (если не задан — 30 дней).
  Свободно = доступно − неоплаченные обязательные платежи до этой даты (включая просроченные).
  Можно в день = свободно / дней. Прогноз остатка = свободно − средние переменные траты × дней
  (средние за последние 60 дней, без платежей по графику; если истории < 14 дней — по бюджету месяца,
  если нет и бюджета — риск кассового разрыва «неизвестен», а не «не прогнозируется»).
- **План по датам (`plan`, раздел «План»):** то же, но до любой даты и через несколько выплат. Ожидаемые доходы
  здесь учтены **как план**; рядом считается, когда закончатся реальные деньги, если они не придут.
  Показывает минимальный остаток и все периоды ухода в минус — не только итог на конец периода.
  Повседневные траты без истории берутся из бюджета: лимит месяца / дней в месяце.
- **Средние за месяц** (доход, расходы, подушка, темп погашения) берутся только по **полностью
  учтённым** месяцам — месяцы до начала учёта не занижают средние.
- **Подушка:** база = средние (потребление + погашение тела долга) за 3 полных месяца; если истории нет —
  обязательные платежи месяца + бюджет месяца. Подушка = накопительные счета и вклады.
- **План погашения долгов:** помесячная модель (проценты = остаток × ставка / 12, освободившиеся
  минимумы переходят на следующий долг). Три порядка: рекомендуемый (просрочка → ваш приоритет →
  ставка → остаток), лавина (ставка), снежный ком (остаток). Неизвестная ставка считается как 0 % —
  с пометкой, что проценты занижены.

### Распределение зарплаты (/salary)

1. Фактически доступно (только поступившие деньги).
2. − обязательные платежи до следующего дохода (с просроченными).
3. − защищённые расходы на жильё, еду, транспорт, здоровье до следующего дохода
   (по средним за 60 дней, иначе — по бюджету; если неизвестно — распределение не предлагается).
4. − страховой буфер 10 % от п. 2 и 3.
5. = свободный остаток, который делится по правилам:
   просрочки по долгам — первыми; подушка < 1 мес.: 40 % резерв / 40 % долги / 20 % личное;
   1–3 мес.: 50 % долги / 30 % резерв / 20 % личное; ≥ 3 мес. с долгами (кроме ипотеки): 70 / 10 / 20;
   ≥ 3 мес. без долгов: 50 % капитал / 30 % резерв / 20 % личное. Досрочные платежи идут по
   рекомендуемому порядку. **Инвестиции не предлагаются, пока есть потребительские долги и подушка < 3 мес.**
6. Бюджет на повседневные траты в день = (защищённые + личные) / дней до дохода.

## Проверки корректности

`python -m fin check` (и раздел «Аудит») выполняет:

- целостность файла SQLite и внешних ключей;
- остатки счетов SQL-запросом **совпадают** с независимым пересчётом циклом по операциям;
- **тождество денежного потока** за текущий месяц: изменение суммы всех счетов = доходы + займы +
  возвраты мне + корректировки − потребление − погашение тела долга − выданные займы;
- чистый капитал равен сумме составляющих;
- нет служебных категорий в доходах/расходах (двойного учёта), некорректных переводов и платежей;
- нет отрицательных долгов и дебиторки, предупреждения: операции раньше начального остатка,
  проведённые операции в будущем, просроченные ожидаемые поступления, отрицательные остатки,
  долги без ставки/минимального платежа.

Ввод тоже проверяется: нельзя погасить больше остатка долга, вернуть больше, чем должны,
перевести на тот же счёт, указать основной долг больше платежа.

Автотесты (сценарии с заранее посчитанным ответом):

```bash
cd finance
python -m unittest discover -s tests -v
```

## CSV: импорт и экспорт

Разделитель `;`, UTF-8 с BOM (открывается в Excel), суммы `12345.67` (при импорте принимается и `12 345,67`).
Экспорт — с названиями вместо id, поэтому файл можно править и импортировать обратно.

Операции (обязательны Дата, Вид, Сумма):

```
Дата;Вид;Статус;Сумма;Счёт;Счёт зачисления;Категория;Подкатегория;Долг;Основной долг;Дебитор;Цель;Описание
2026-10-05;Доход;Проведена;150000;Дебет;;Зарплата;;;;;;Зарплата за сентябрь
2026-10-06;Расход;;1234,50;Дебет;;Продукты и питание;Магазин;;;;;
2026-10-10;Платёж по долгу;;15000;Дебет;;;;Банк А;9000;;;
2026-10-11;Перевод между своими счетами;;10000;Дебет;Накопительный;;;;;;;
```

«Вид» — по-русски («Доход», «Расход», «Перевод», …) или кодом (`income`, `expense`, `transfer`,
`debt_payment`, `debt_draw`, `debt_adjust`, `lend`, `lend_return`, `adjustment`). Статус пустой = «Проведена».

Импорт **атомарный**: если хоть одна строка с ошибкой, не записывается ничего, и выводится список ошибок
по строкам. Есть режим «Проверить без записи» (`--dry-run`). Дубликаты определяются по содержимому:
повторный импорт того же файла ничего не задвоит, а две одинаковые покупки в одном файле сохранятся обе.
Счета, долги, дебиторы и цели должны существовать заранее (их тоже можно импортировать: `--table accounts` и т. д.).

```bash
python -m fin export                          # всё в zip: CSV всех таблиц + полный отчёт report.md
python -m fin export --table transactions --start 2026-10-01 --out октябрь.csv
python -m fin import выписка.csv --dry-run
python -m fin import выписка.csv
```

## Резервное копирование

- `python -m fin backup` или кнопка в разделе «Данные» — копия в `finance/data/backups/`
  (штатный backup API SQLite, безопасно при запущенном интерфейсе; копия проверяется на целостность).
- Автокопии создаются перед каждым импортом и восстановлением; хранятся последние 30 (ручные не удаляются).
- Восстановление: `python -m fin restore ИМЯ_ФАЙЛА` или кнопка «восстановить» — текущее состояние перед этим
  сохраняется отдельной копией, так что восстановление можно откатить.
- `python -m fin backup --dir E:\finance-backup` — копия на внешний диск.
- Полный перенос: скопируйте файл `finance/data/finance.db`.

## Конфиденциальность

- Сервер слушает только `127.0.0.1`, проверяет заголовок Host и CSRF-токен формы — другие сайты
  в браузере не могут ни прочитать, ни изменить данные.
- Данные не покидают компьютер; база и копии исключены из git (`/finance/data/` в `.gitignore`).
- Храните копии на зашифрованном диске/в зашифрованном архиве; не публикуйте файл базы.
